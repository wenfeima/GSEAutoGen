## 结论

### 1. 官方 API 完全可用，无 secret 保护
- `C_AssistedCombat.GetRotationSpells()` 返回真实 spellID 数组 ✅
- `C_AssistedCombat.GetNextCastSpell()` 仅在**战斗 + 有目标**时有值
- 未触发 `IsSecretValue` 保护

### 2. GetNextCastSpell 是"实时值"，不能直接写进静态宏
- 宏是静态文本，按下时执行写死的顺序
- 实时推荐随战斗状态每时每刻变化
- ⇒ **只能抄技能池（GetRotationSpells）的"内容"，不能抄实时单值**

### 2b. 【重要修正】技能池的**顺序 ≠ 优先级**（第二次实测证伪）
第二次（战斗中、有目标）实测：

```
pick (GetNextCastSpell): 盾牌猛击      ← 实时推荐 = 盾牌猛击
4. 盾牌猛击 (23922)  <- AC pick        ← 但它在池子里只排第 4
[1] tracks the live pick: NO (list[1] != GetNextCastSpell)
```

- 池子第 1 位是「雷霆一击」，但官方实际推荐的是「盾牌猛击」（第 4 位）
- **官方自己都标注 `list[1] != GetNextCastSpell`**
- ⇒ **`GetRotationSpells()` 只是一个"可用技能全集"，其数组顺序没有优先级含义**

**修正后的结论**：
| 数据 | 能用来干什么 |
|---|---|
| `GetRotationSpells()` 的**顺序** | ❌ 不能当优先级（已证伪） |
| `GetRotationSpells()` 的**内容** | ✅ 当技能全集，保证不漏技能 |
| `GetNextCastSpell()` | ✅ 唯一的真实优先级信号，但是**实时值** |

⇒ **想要优先级，只能靠"采样统计"**：战斗中高频读 `GetNextCastSpell()`，
按出现频率统计，频率最高的就是真正的优先级顶端。这是唯一可行路径（方案 A）。
